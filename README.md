# НарядAI — интеллектуальная система выдачи и контроля нарядов

> «Наряд выдан — ИИ на контроле». Кейс №1 АО «Костанайские минералы», Qostanai AI Industry Hackathon 2026.

**Демо:** https://naryad-ai-eta.vercel.app — PWA, на Android ставится через меню браузера «Установить приложение».

Мастер смены выдаёт наряд с телефона за ≤ 6 нажатий, исполнитель получает push (Telegram и в приложении), принимает и закрывает наряд с фото, а ИИ:
- следит за сроками;
- проверяет выполнение и фото «до/после»;
- пишет отчёты;
- считает рейтинг;
- находит проблемное оборудование.

## Тестовые учётные записи

Вход по табельному номеру и ПИН (6 цифр, крупная цифровая клавиатура). Тестовые ПИН-коды по ролям лежат в [`data/demo_accounts.json`](data/demo_accounts.json).

| Роль | Табельный № | Что видит |
|---|---|---|
| Мастер смены | 1001 (Жуматов С.), 1002 | Панель смены, выдача нарядов, проверка, аналитика |
| Исполнитель | 3001 (Ахметов Е., слесарь), 3002…3015 | Свои наряды, кнопки статусов, закрытие, свои оценки |
| Руководитель | 2001 | Дашборд, отчёты, рейтинг, аномалии |
| Администратор | 9001 | Всё + справочники |

Перед показом мастер нажимает «Настройки → Подготовить смену к демо»: кто-то уже в работе, у кого-то очередь.

## Архитектура

```
Телефон мастера / исполнителя (PWA) ─┐                 ┌─► Telegram-бот (push + кнопки)
Веб-панель руководителя             ─┼─► Supabase ─────┤
                                      │   Postgres + RLS ├─► Edge Function ai-review ──► Claude API
                                      │   Realtime (≤5 с) │      (триггер: наряд «Исполнено»)
                                      │   Auth (таб.№+ПИН)└─► Edge Function ai-insights ─► Claude API
                                      │   Storage (фото)        (аномалии, сводка, шифр, ассистент)
                                      └── pg_cron → check_deadlines() каждые 30 с
```

**Принципы:**
- Наряд меняется **только** через SQL-функции. Поэтому каждый переход гарантированно пишется в журнал `order_events`, а права проверяются в одном месте.
- **Цифры считает код, ИИ их формулирует.** Статистика ищет факты, Claude пишет вывод и рекомендацию. Модель не выдумывает числа.
- **Безопасность:**
  - решение ИИ — рекомендация, последнее слово за мастером: он может изменить оценку;
  - ФИО сотрудников не уходят в ИИ, только инициалы или ничего;
  - RLS по ролям;
  - анонимный ключ не может вызвать ни одной функции;
  - служебные функции доступны только cron, триггерам и Edge Functions.
- **Без ключа Claude система работает в режиме правил:** проверка полноты, материалов против нормы, времени, повтора фото. Claude добавляет смысловую проверку работ и фото.
- **Интеграция с 1С, ERP и ТОиР:** справочники и наряды лежат в Postgres с REST API (PostgREST). Выгрузку можно делать SQL-представлениями или вебхуком на `order_events`.

## ИИ-модули (раздел 6 ТЗ)

| Модуль | Как работает |
|---|---|
| 6.1 Контроль сроков | Правила в БД. Напоминание за 30 мин, просрочка исполнителю и мастеру в формате ТЗ, повтор каждые 15 мин, руководителю через 60 мин. Не принят за 10 мин (аварийный за 3) — эскалация мастеру с кандидатом на замену |
| 6.2 Проверка выполнения | 1) Правила: полнота, шифр, фото «после» для внеплановых, материалы против нормы по шифру (×2 — нарушение), время против норматива. 2) Claude Opus 5.5 (structured outputs): соответствие работ проблеме, логичность материалов, фото. Жёсткое нарушение → «требует доработки», уверенность < 0,6 → «нужна проверка мастером» |
| 6.3 Фото «до/после» | dHash на телефоне + сравнение с фото всех нарядов (повтор старого фото). Claude видит оба фото: то же ли оборудование, устранена ли проблема, мусор, кожухи. Оценка 1–5 |
| 6.4 Отчёты | Исполнителю: оценка, что хорошо, что улучшить, время против норматива. Мастеру: всё, плюс хронология и фото |
| 6.5 Аномалии | `_shared/anomalies.ts` (порт `analytics/find_anomalies.py`): топ оборудования, повтор шифра, поломки после ППР, качество исполнителя, перерасход, тренд и прогноз. Claude переписывает выводы простым языком |
| 6.6 Рейтинг | 35% качество + 25% в срок + 20% без доработок и повторов за 7 дней + 15% объём×сложность + 5% дисциплина. Пояснение по клику |
| 6.7 Ассистент | Claude отвечает по снимку смены. Без ключа отвечает правилами на «кто свободен» и «что просрочено» |

**Модель:** `claude-opus-5-5`, effort `low`, structured outputs. Включены серверные `fallbacks: "default"`: при отказе классификатора запрос выполняет рекомендованная модель.

## Запуск

### Supabase
1. Создайте проект.
2. В SQL Editor выполните по порядку `supabase/migrations/0001` … `0006`. Нужны расширения pg_cron и pg_net, миграции их включают.
3. Загрузите данные `data/seed.sql`. Через psql: `psql "<connection string>" -f data/seed.sql`.
4. Выполните `supabase/seed_auth.sql` — это учётки для всех сотрудников.
5. Пропишите адрес функций и anon-ключ, чтобы БД могла вызывать Edge Functions:
   ```sql
   insert into private.app_secrets(key, value) values
     ('functions_url', 'https://<ref>.supabase.co/functions/v1'), ('anon_key', '<anon key>')
   on conflict (key) do update set value = excluded.value;
   ```
6. Edge Functions из `supabase/functions/`: `ai-review`, `ai-insights`, `tg-notify`, `tg-setup` (с проверкой JWT) и `tg-webhook` (без JWT, проверяет секрет Telegram).
7. Секреты Edge Functions (Dashboard → Edge Functions → Secrets):
   - `ANTHROPIC_API_KEY` — ИИ-проверка с Claude;
   - `TELEGRAM_BOT_TOKEN` — от @BotFather.

   Затем в приложении: «Настройки → Настроить бота».

### Приложение
```bash
cd web && npm install
cp .env.example .env    # URL и anon-ключ Supabase
npm run dev             # npm run dev -- --host — открыть с телефона в той же сети
```
Деплой: `npx vercel deploy --prod` из `web/`.

### Тесты
```bash
cd supabase/tests && npm install && npm test        # 32 проверки SQL-логики на Postgres (PGlite)
cd web && node --env-file=.env scripts/e2e-smoke.mjs # сквозной тест против живого Supabase (15 проверок)
python data/generate.py && python analytics/find_anomalies.py   # данные и аналитика
```
